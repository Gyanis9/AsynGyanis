# 安全加固与部署基线

[返回文档导航](文档导航.md)

本文记录 2026-10-27 网络安全加固后的默认值、升级影响、部署控制与仍然存在的残余面。协议行为细节见 [网络编程](网络编程.md)，启停、证书自动化与多 worker 见 [部署与运维](部署与运维.md)。本文与代码默认值冲突时以代码为准，并应同步修正本文。

## 默认值

| 项 | 新默认 | 配置或入口 | 关闭或调整 | 生效范围 |
| --- | --- | --- | --- | --- |
| 请求头总时限 | 30 秒 | `server.limits.request_header_timeout_ms`；`HttpServerLimits::requestHeaderTimeout` | 0 关闭；调大或调小按毫秒写 | h1/h2/h3 |
| QUIC 地址验证 | 开启，令牌有效期 30 秒 | `QuicServer::Configuration::addressValidationTokenLifetime` | 0 关闭；地址验证密钥见「多 worker」 | QUIC 服务端 |
| TLS 客户端最低版本 | TLS 1.2 | `Core::TlsPolicy::minimumProtocolVersion`；未给下限时 `TlsContext` 按角色补 1.2 | 只能设 1.2 或 1.3；枚举里没有 1.0/1.1 | 经 `TlsContext` 的出站；QUIC 恒 1.3 |
| JWT 过期声明 | `exp` 必填 | `JwtVerifier` / `validateJwtClaims` | 不用本校验器即不受此约束；`iss`/`aud` 仍由调用方给 | JWT 校验 |
| JWKS/OAuth 端点传输 | 非回环必须 https | `JwksKeyProvider`；OAuth 的 token、device authorization 与 introspection 端点 | 无关闭开关；回环的 `127.0.0.1`、`::1`、`localhost` 可用 http | 认证客户端；授权端点 `authorizationUrl` 不经本端校验 |
| wss 对端校验 | 必须开启 | `WebSocketClient::Configuration::clientTls` | 走 wss 时上下文须已调用 `enableClientPeerVerification()`；明文 ws 不受影响 | WebSocket 客户端 |
| 重定向降级 | 拒绝 https → http | `HttpClient` 的 `followRedirects` | 不跟随重定向（默认）即不触发；降级命中时原样交回 3xx | HTTP 客户端 |
| 静态预压缩变体 | 根内复核 | `staticPrecompressedVariants()` | 关掉变体即回到主文件；根内复核不可单独关闭 | 静态文件服务 |
| OCSP 装订 | 请求；收到即校验，未装订放行 | `TlsContext` 客户端角色；`TlsSocket::handshake()` | 服务端不装订即可；装订校验失败即拒握手 | 经 `TlsSocket` 的 TLS 客户端 |

几项口径：

- 请求头总时限的起点按通道不同：h1 从本条请求首字节起算；h2 从 HEADERS 帧解码完成、进入头块拼接时起算；h3 从 HEADERS 帧收齐时起算。三条通道都以请求头收齐为终点，帧内逐字节滴送不计入预算（见「残余面」）。正文没有对应总时限，仍由 `read_timeout_ms`、正文大小上限与连接限额兜底。三条通道的收口形态不同：h1 到点由连接截止时间收口，不回 408；h2 先排 GOAWAY（`ENHANCE_YOUR_CALM`）再收口连接；h3 复位该流（`H3_REQUEST_CANCELLED`），连接与其他流继续。
- QUIC 地址验证开启后，不带令牌的新连接首包先吃一条 Retry；本引擎客户端已支持按 RFC 9000 §17.2.5.2 带令牌重发同一份 ClientHello。令牌有效期就是旧密钥的验签窗口。
- TLS 客户端的 1.2 下限只在策略没给最小值时补；`TlsPolicy` 只接受 1.2 与 1.3，不能把下限降回 1.0/1.1。服务端角色同样补 1.2，QUIC 由 RFC 9001 固定为 1.3。
- OCSP 校验覆盖 DER 编码、响应状态、签名链、CertID（按响应声明的摘要算法）、有效性与 GOOD 状态；`thisUpdate` 超过 7 天即判过期。未收到装订不做强制。
- 静态预压缩副本命中后先 `weakly_canonical`，再过静态根包含判定；越界或规范化失败只跳过该副本，主文件照常服务，不回 403。

## 升级影响

### 慢速客户端与请求头

默认 30 秒会把「首字节到请求头收齐」超过 30 秒的连接切断，即使每次读取之间都短于 `read_timeout_ms`。慢速链路、调试代理或人为限速的压测可能因此失败。

调整方式：

- 按部署写 `request_header_timeout_ms`（例如 60000）；确实要关掉时写 0，此时只剩 `read_timeout_ms` 的相邻读间隔与连接限额。
- 改 `server.limits.*` 走 SIGHUP 或文件监听，只影响此后新建的连接；在途连接保持旧值。

### 无 Retry 的 QUIC 客户端

地址验证默认开启后，服务端对不带令牌的首个 Initial 回 Retry，不为它建状态。实现了 Retry 的客户端照常握手；不处理 Retry 的客户端会被挡在第一条 Initial 上。

调整方式：

- 优先升级客户端实现。QUIC 要求客户端能处理 Retry，这不是可选项。
- 确实无法升级时，在自建 `QuicServer::Configuration` 里把 `addressValidationTokenLifetime` 设为 0。`ReferenceServer` 没有暴露这个开关，默认即 30 秒。

### 无 `exp` 的 JWT

`validateJwtClaims` 现在要求载荷里必须有数值型 `exp`；缺失即拒，不再把「没有到期时间」当成「永不过期」。`nbf` 仍可选，`iss`/`aud` 仍只在调用方给出期望时校验。

调整方式：

- 让签发方带 `exp`，并保证本端时钟与签发方偏差在 `JwtClaimExpectations::clockSkew`（默认 60 秒）以内。
- 确实不能改签发方时，改用不依赖本校验器的通道，不要把「跳过声明校验」当成默认方案。

### 明文认证端点

JWKS 与 OAuth 的 token、device authorization、introspection 端点只允许 https，或主机名为 `127.0.0.1`、`::1`、`localhost` 的 http。非回环明文端点在构造或启动时直接拒绝，不回退、不静默直连。授权端点 `authorizationUrl` 只交给浏览器跳转，本客户端不发请求，也不校验它的传输方式；调用方要自行确保它是 https。

调整方式：

- 换成 https；本地开发继续用回环 http。
- 回环 http 仍有一条残余风险：出站客户端默认认环境代理，307 也可能把请求带到别处。跑认证流量时用 `no_proxy` 排除回环，或对该客户端显式关掉环境代理与重定向跟随。

### 未开校验的 wss

`Configuration::clientTls` 非空即走 wss；此时上下文没有开启对端证书校验，`connect` 会在解析 DNS、建 TCP 之前返回 `TlsSetupRejected`。

调整方式：

- 对持有的 `TlsContext` 调用 `enableClientPeerVerification()`，再发起 connect。
- 不要把「没配 CA」当成「先不校验」：`TlsContext` 客户端角色不会替调用方打开校验，HTTP 与 QUIC 客户端在构造时自己调 `enableClientPeerVerification()`，WebSocket 的上下文归调用方，必须自己调。

### https → http 重定向

`followRedirects` 开着时，下一跳若是 https 降到 http，客户端停止跟随，把对端那条 3xx 原样交回，并记一条 WARN 说明停止原因。http → https、https → https 与 http → http 的既有跟随规则不变。

调整方式：

- 调用方按普通 3xx 处理；需要继续取内容就自己显式请求 https 目标，不要把降级重新塞回自动跟随。
- 上游确实只提供 http 时，改由本端做 TLS 终止或换源，不要依赖客户端降级。

### HTTP/2 请求目标

非 CONNECT 请求的 `:path` 必须以 `/` 开头；`*` 只允许 OPTIONS。普通 CONNECT 必须省略 `:path` 与 `:scheme`；带 `:protocol` 的扩展 CONNECT 恰好相反，必须同时给出 `:scheme` 与非空 `:path`，并带非空 `:authority`（RFC 8441 §4）。不合规按流错误 `PROTOCOL_ERROR` 处理（RST_STREAM），连接继续服务其它流。此前 `no-slash` 这类目标会一路走到路由并变成 404。

调整方式：客户端按 RFC 9113 §8.3.1 发送 origin-form；h1 侧本来就是同一条口径。

### HTTP/2 客户端响应校验

h2 客户端现在校验响应头字段名与值字符、连接特定头、`te` 取值、重复 `content-length` 是否一致，并在 END_STREAM 时比对声明长度与实际 DATA 总长。HEAD、204、304 跳过长度比对；响应头与尾字段仍分两张表。

调整方式：

- 修上游：去掉 `connection` / `keep-alive` / `proxy-connection` / `transfer-encoding` / `upgrade` 这类连接特定头，保证 `content-length` 与实际正文一致。
- 204 带非零 `content-length` 目前不会被拒，只是跳过长度比对；尾字段里的 `content-length` 与 `host` 也不会被拒。这两条见「残余面」，不要把它们当成已校验。

### TLS 版本与 OCSP

客户端默认最低 TLS 1.2，连 TLS 1.0/1.1 的对端会握手失败；策略里没有把下限降回去的档位。经 `TlsSocket` 的 HTTP/WebSocket 出站客户端会请求 OCSP 装订，服务端装了响应就校验，装订坏了（签名链、CertID、有效期、状态不是 GOOD）直接拒握手；不装订照常连接。Redis 与 QUIC 客户端只请求装订、不校验，见「残余面」。

调整方式：

- 对端升级到 TLS 1.2 及以上；老设备只能在前置代理上做终止与转接。
- 服务端换掉过期或错误的装订响应；`thisUpdate` 超过 7 天的响应会被判过期，刷新间隔要短于这个窗口。

### QUIC NEW_TOKEN

客户端收到 NEW_TOKEN 时只校验非空，不存储、不跨连接复用；零长令牌按 `FRAME_ENCODING_ERROR` 收口。服务端收到客户端发来的 NEW_TOKEN 按 `PROTOCOL_VIOLATION` 收口。0-RTT 仍未实现。

调整方式：自定义客户端不要向服务端发送 NEW_TOKEN；服务端不能指望客户端带回上一次的令牌。

## 部署控制

### PROXY 协议

`TcpServer::setProxyProtocolRequired(true)` 会让每条新连接先读一条 PROXY 协议头（v1 文本行或 v2 二进制块），读到的来源地址成为限额键、`remoteAddress()` 与日志里的客户端身份。头本身没有任何鉴权，**只有在该端口只有代理能连进来时才开**；对公网敞开等于让每个客户端自己挑一个来源 IP 来占限额。读头时限固定 3 秒，头必须单独成段送到；没带头或不规范会收口连接并留 WARN。`ReferenceServer` 未提供命令行开关，这一项由装配代码设置。

### 环境代理

出站客户端默认认 `http_proxy` / `https_proxy` / `no_proxy`（大小写都认、小写优先），与 curl/Go 的语义一致；显式 `HttpProxyPolicy` 字段优先于环境。要整体关掉环境识别，传一份 `consultEnvironment=false` 的策略；`HttpClient` 在构造时把策略读一次冻结，静态 `get/post/send` 每次现读。代理配置错误一律拒绝而不是静默直连，错误文案里的凭据会打码。

### 会话票据

会话票据默认开启（`server.tls.session_tickets`）。多进程或多机共享同一份密钥文件：`--ticket-key` 可给多份，首份签发新票据，其余只用于解开轮换窗口内的旧票据；`QuicServer::Configuration::sessionTicketKeyFiles` 同理。不装载密钥文件时每个上下文自己随机生成一份，跨 worker 不通用，证书换代后旧票据也全废。

轮换走「文件替换 + reload」：把新密钥放到列表首位、旧密钥留在列表里，替换文件内容后走证书 reload 那条路径（`HttpsServer::reloadCertificate()`、`QuicServer::reloadCertificate()` 或 ACME 的装回回调）。reload 会按原路径重读票据密钥，任一份读不出来整次换代失败、旧上下文继续服务。**没有进程内定时自动轮换**；等旧票据全部过期后再把旧密钥从列表里摘掉。

### CRL 与 OCSP

CRL 仍只在显式配置 `server.tls.revocation_list_file` 时启用；只支持单个文件，PEM/DER 都行，一份文件里可放多张 CRL。`revocation_covers_whole_chain` 决定只查对端那一张还是链上每张。启用了却没有覆盖到发证 CA 的列表时，握手一条也不成——这是刻意的方向：列表没同步到就当成没吊销，比先拒掉更危险。换 CRL 文件后同样走证书 reload 或重启。

服务端 OCSP 装订由 `HttpsServer::loadOcspResponse()` 显式装载，未装载就不装订；reload 按原路径重读。客户端侧 `thisUpdate` 的 7 天上限见「TLS 版本与 OCSP」。

### 多 worker 与 QUIC 地址验证

地址验证默认开启后，多进程 worker 必须共享同一份 `addressValidationKey`（至少 16 字节）。各进程随机自造时，客户端带着 A 进程签的令牌撞到 B 进程必然验不过，表现为握手偶尔白走一轮。`rotateAddressValidationKey()` 可以换签发密钥；密钥集最多保留当前与上一把，上一把签出的令牌在有效期内仍可验签，更早的密钥在下次轮换时即被丢弃。本实现不做定时轮换。

`samples/Net/ReferenceServer.cpp` 里给的是 32 字节固定值 `0x52`，只服务参考实现与多 worker 测试。样例二进制没有命令行或环境入口注入这把密钥；生产部署要自建装配、从密钥文件或环境读取，不能直接拿样例二进制上线。同文件的 `--ticket-key` 与 `--stateless-reset-key` 都是文件入口，没有硬编码密钥。

## 残余面

以下各项在本次加固后仍然存在，部署与评审时要按这里的边界理解，不要当成已关闭。

| 面 | 现状与上界 | 兜底与后续 |
| --- | --- | --- |
| h2 单个 HEADERS 帧逐字节滴送 | 头块预算从 HEADERS 帧解码完成、进入拼接时起算；帧本身没收齐之前不计时。单个帧上限 16 KiB，逐字节滴送的理论上界约 16 KiB × `read_timeout_ms`（默认 60 秒），量级是十余天 | 受帧上限、连接限额与并发上限约束；要收紧需让帧解码器暴露半帧起点并接入头块预算 |
| h3 头段计时起点 | 只在 HEADERS 帧收齐、交给 QPACK 之前起算；同一帧内的字节滴送不受这条预算管 | QUIC 空闲超时（默认 30 秒，需持续有报文才不触发）、流控与头块字节上限兜底；QPACK blocked 的流已被覆盖，因为计时在解码前就开始 |
| 正文总时限 | 未默认开启。慢速正文只要每次读取不超过 `read_timeout_ms` 就能一直续 | 正文大小上限（默认 8 MiB）、连接数/单 IP 限额与可选的在途正文内存预算；需要总时限时由前置代理或业务自行加 |
| NEW_TOKEN 存储 | 客户端不存储、不复用；零长令牌按 `FRAME_ENCODING_ERROR`，非空令牌收到即丢 | 没有 0-RTT 与跨连接令牌复用；服务端收到客户端 NEW_TOKEN 已按 `PROTOCOL_VIOLATION` 收口 |
| 客户端空 token 分支 | 恶意服务端发零长 NEW_TOKEN 的分支没有自动化用例（需新增 1-RTT 注入缝，收益低） | 代码路径按 RFC 9000 §19.7 收口；回归依赖协议用例与代码审查 |
| Redis 与 QUIC 客户端的装订校验 | 两者都经 `TlsContext` 客户端角色请求 OCSP 装订，但握手走各自的 `SSL_connect` / `SSL_do_handshake`，没有调用 `verifyStapledOcspResponse` | HTTP 与 WebSocket 经 `TlsSocket` 的路径已校验；Redis/QUIC 目前只做到「请求」，收到坏装订不会拒握手 |
| h2 客户端尾字段 | 尾字段的字段名与值字符会校验，但 `content-length` 只在最终响应头块里记录，尾字段里的 `content-length` 与 `host` 都不会被拒 | 只有 h3 服务端在尾段拒这两类；h1/h2 服务端仍有缺口（见下一行）；尾字段的长度不参与正文定界，风险限于下游把尾字段当头部读 |
| h1 与 h2 服务端尾字段 | h1 解析器只在尾段丢弃 `content-length` 与连接特定头，`host` 照收；h2 服务端只在交付时摘掉 `content-length`，`host` 仍交给业务 | h3 服务端已拒 `content-length` 与 `host`；要收紧需让 h1/h2 的尾段判据与 h3 对齐 |
| h2 客户端 204 带非零 `content-length` | 204/304/HEAD 跳过声明长度与 DATA 总长的比对，204 带非零 `content-length` 也不会被拒 | 204 按定义没有正文；要收紧需在头块解析时按状态码判 |
| 同一 DATA 帧越限后的 RST | 一帧 DATA 越正文上限时先发 `CANCEL`；若同一帧还带 END_STREAM 且声明长度不符，随后会再发一枚 `PROTOCOL_ERROR` | 对端按 RFC 9113 §5.4.2 忽略第二枚；连接状态不受影响，属可接受的重复复位 |
| h2 客户端 SETTINGS 头列表上限 | 通告值取 `HpackDecoderLimits{}` 的默认 64 KiB，`Http2ClientConnection::Config` 没有对应字段 | 要改只能改库默认或新增配置项；服务端侧仍可用 `maximumHeaderListSize` 调 |
| T9 符号链接用例 | Windows 上没有建符号链接权限时 `GTEST_SKIP`，本机不证伪；Linux CI 的 `tests/Net` 会真正执行 | 建议 CI 检查该用例未被跳过；否则「根内链接指向根外」只剩代码审查 |
| `queueSpacePackets` 复杂度基线 | 函数体 103 行，`scripts/complexity-baseline.json` 仍记 123，松出的预算会掩盖后续小改动 | 功能与安全行为不受影响；后续按实测重钉基线，避免继续用旧读数兜底 |
| `docs/网络编程.md` 的 `path:line` | TLS/QUIC 相关引用已按本次代码位置刷新；追溯门只验路径存在、行号不越界且不指空行，不验语义 | 改代码后仍需人工同步；新文档不在 `check-arch-traceability.py` 的扫描清单里，不能只靠门禁发现漂移 |
