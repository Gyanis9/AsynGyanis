# 入门与构建

[返回文档导航](文档导航.md)

本文说明支持平台、构建依赖以及将 AsynGyanis 作为库使用的方法。命令默认在仓库根执行。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 及以上，或 Linux；不支持 macOS/BSD |
| 编译器 | MSVC ≥ 19.40、GCC ≥ 13 或 Clang ≥ 17，并具备所需 C++23 标准库支持 |
| CMake | 顶层 `cmake_minimum_required` 为 3.20；使用仓库预设需要 ≥ 3.25 |
| 构建生成器 | Ninja，两个现有预设均使用它 |
| 包管理 | Conan 2；依赖与库包仅维护 Conan 路线 |
| 辅助工具 | Python，用于安装 Conan、运行示例矩阵与验证脚本 |

[CMakePresets.json](../CMakePresets.json) 使用 schema version 6，CMake 3.20 不能读取该预设文件；不要把顶层 CMake 最低版本理解为预设最低版本。编译器版本满足表格也不代表其标准库组件齐全，配置期的能力探测结果仍需保留。

Linux 默认使用 epoll；Windows 使用 IOCP。Linux 可显式选择 io_uring，需要内核 5.6+，还要求宿主与容器策略允许 `io_uring_setup`。没有 kqueue 后端，其他系统在配置阶段被拒绝。Linux 每线程监听形态使用 `SO_REUSEPORT`，需内核提供相应支持。

## 依赖版本

版本来源为 [conandata.yml](../conandata.yml)。根 [conanfile.py](../conanfile.py) 为开发构建安装依赖，[库包配方](../packaging/conan/conanfile.py) 负责对外交付。

| 库 | 版本 | 用途 |
|----|------|------|
| [nlohmann_json](https://github.com/nlohmann/json) | 3.12.0 | JSON 值模型与解析/序列化（Base 公开接口） |
| [yaml-cpp](https://github.com/jbeder/yaml-cpp) | 0.9.0 | YAML 解析（配置加载） |
| [OpenSSL](https://www.openssl.org/) | 3.6.5 | TLS/HTTPS，兼作 QUIC 的加密胶水 |
| [zlib](https://zlib.net/) / [zstd](https://facebook.github.io/zstd/) / [brotli](https://github.com/google/brotli) | 1.3.1 / 1.5.7 / 1.1.0 | 响应正文与 WebSocket 压缩 |
| [mimalloc](https://microsoft.github.io/mimalloc/) | 3.5.1 | 默认启用的全局分配器（`ASYN_WITH_MIMALLOC`，sanitizer 档关闭） |
| [GoogleTest](https://github.com/google/googletest) | 1.17.0 | 单元测试 |
| [SQLite3](https://www.sqlite.org/) | 3.51.3 | 嵌入式数据库驱动 |
| [hiredis](https://github.com/redis/hiredis) | 1.3.0 | Redis 客户端 |
| [libmysqlclient](https://dev.mysql.com/doc/c-api/) | 8.1.0 | MySQL 客户端 |
| [libpq](https://www.postgresql.org/docs/current/libpq.html) | 17.11 | PostgreSQL 客户端 |

JSON、YAML 和 SQLite 为必选依赖。MySQL、PostgreSQL 与 Redis 驱动按可选依赖接入：CMake 未找到对应目标时编译报错桩，调用入口会说明缺少驱动，而不是提供替代数据库行为。实际启用情况查看配置输出与生成的 `AsynGyanisFeatures.h`。

[wepoll](https://github.com/piscisaureus/wepoll) 的 [头文件](../src/Core/EventLoop/wepoll.h) 随仓库分发，仅提供 Windows 后端使用的 `epoll_event` 和事件位定义；它的 AFD 轮询实现不参与运行。

## 使用现有预设

先确保编译器、CMake、Ninja 与 Conan 都在当前终端可用。Conan profile 必须与实际编译器及目标架构一致；新环境可执行 `conan profile detect`，已有自定义 profile 不要无意覆盖。

Linux：

```bash
python3 -m pip install "conan>=2"
conan profile detect
cmake --preset debug
cmake --build --preset debug --parallel
ctest --preset debug
```

Windows：在 Visual Studio Developer Command Prompt 或已加载 `vcvars64` 的终端执行：

```bat
python -m pip install "conan>=2"
conan profile detect
cmake --preset debug
cmake --build --preset debug --parallel
ctest --preset debug
```

配置阶段由 [conan_provider.cmake](../conan_provider.cmake) 自动执行依赖安装，缺少二进制包时从源码构建。常规开发不需要再手工运行一遍 `conan install`。首次配置可能主要耗时在第三方依赖，尤其是 MySQL 客户端。

预设同时提供 configure、build 和 test 入口；`ctest --preset` 在仓库根调用。并行度按可用 CPU 与内存调整，例如 `--parallel 4`，不要照搬其他机器的线程数。

Release：

```bash
cmake --preset release
cmake --build --preset release --parallel
ctest --preset release
```

| 预设 | 构建目录 | 默认检测与优化 |
| --- | --- | --- |
| `debug` | `build/debug` | 开启 `ENABLE_SANITIZERS` |
| `release` | `build/release` | 关闭 sanitizer、启用优化、保留调试信息 |

MSVC 的 Debug 使用 ASan；GCC/Clang 使用 ASan 与 UBSan。MSVC 不提供这里所用的 UBSan/TSan。构建会将 MSVC ASan 运行库复制到仓库内可执行目标旁；容器注解因与未插桩 GoogleTest 的 ABI 标记冲突而关闭，不能把这档当成包含所有容器注解检查的 ASan。ASan 也会增加栈和内存开销。

## 构建选项

| 选项 | 默认 | 用途与限制 |
| --- | --- | --- |
| `BUILD_SHARED_LIBS` | OFF | 五个模块构建为共享库；Conan 库包仍只提供静态形态 |
| `ENABLE_SANITIZERS` | OFF，Debug 预设 ON | ASan；GCC/Clang 另带 UBSan |
| `SANITIZE_THREADS` | OFF | TSan，不能与 ASan 同开；MSVC 不支持 |
| `ASYN_WITH_MIMALLOC` | ON | 全局分配器替换（生产默认）；与两种 sanitizer 开关互斥，debug 预设与 TSan 档显式关掉 |
| `ASYN_WITH_IO_URING` | OFF | Linux 后端替换，Windows 配置时拒绝 |
| `ASYN_ENABLE_HARDENING` | ON | 编译/链接加固；sanitizer 开启时不叠加 |
| `ASYN_ENABLE_COVERAGE` | OFF | gcov 风格覆盖插桩；MSVC 不支持 |
| `ASYN_BUILD_TESTS` | ON | 测试与热路径微基准 |
| `ASYN_BUILD_SAMPLES` | ON | 自检示例与 ReferenceServer |
| `ASYN_ENABLE_INSTALL` | ON | 安装规则与 CMake 包配置 |
| `DATABASE_WITH_MYSQL` / `POSTGRES` / `REDIS` | ON | 对应驱动依赖探测，缺库时使用报错桩 |

不需要下载或编译 MySQL 依赖时，根开发配方还支持非空环境变量 `ASYN_SKIP_MYSQL_DEPS`。它控制 Conan 依赖清单，不等同于 CMake 的驱动开关；在干净构建中可同时设置：

```bash
ASYN_SKIP_MYSQL_DEPS=1 cmake --preset debug -DDATABASE_WITH_MYSQL=OFF
```

Windows 用 `set ASYN_SKIP_MYSQL_DEPS=1` 后执行相同 CMake 命令。CMake 缓存会保留显式覆盖项；恢复默认时应明确重设对应选项。

## 安装与消费

安装 Release 构建：

```bash
cmake --install build/release --prefix install
```

消费工程将安装前缀加入自己的 `CMAKE_PREFIX_PATH`，并保证 Conan 提供的传递依赖可发现，然后链接所需组件：

```cmake
find_package(AsynGyanis REQUIRED COMPONENTS Net)
target_link_libraries(app PRIVATE AsynGyanis::Net)
```

不指定 `COMPONENTS` 时请求全部五个模块。请求 `Net` 会带出 `Core`、`Base`、`Platform`；仅请求 `Base` 不会因此查找 OpenSSL 与 HTTP 压缩库。组件名错误会被包配置拒绝，外部依赖集合由各模块在配置阶段登记。

库包创建入口：

```bash
conan create packaging/conan --build=missing
```

库包版本从顶层 `project(VERSION ...)` 读取。分发配方关闭测试与示例，`with_mysql` 和 `with_postgres` 默认 false；需要时显式启用对应 Conan 选项。开发配方的默认依赖集与分发配方的可选驱动默认值不是同一个概念。

### ABI 与运行库

- 公开接口包含 `std::string`、`std::vector` 等标准库类型，生产方与消费方必须保持编译器、CRT、标准库及 ABI 相关配置一致；导出宏不提供跨工具链二进制兼容。
- Debug 安装包会传递相应的 ASan/容器注解接口要求。外部可执行体运行时仍需能找到 ASan DLL；不需要插桩的部署使用 Release 包。
- OpenSSL 静态链接可能使库与消费工程各有一份实例。不要将 `TlsContext::nativeHandle()` 交给消费方另一份 OpenSSL 操作。
- Windows 共享构建将 DLL 与可执行体放在所选构建目录的 `bin/`，例如 `build/release/bin/`；默认静态构建的示例仍在 `build/release/samples/`。
- 加固选项为仓库目标的 PRIVATE 策略，不会替外部消费者加固最终可执行体。消费方应配置并验证自己的链接策略。

构建后运行方式见 [部署与运维](部署与运维.md)，门控测试与完整验证入口见 [测试与验证](测试与验证.md)，优化选项的测量方法见 [性能测试](性能测试.md)。
